## Активная задача

### Задача «SEND: срабатывает только с первого клика» [EXECUTED]
- **Цель:** Отчёт: первый клик SEND в окне Edit Macro отправляет команду, последующие (включая после закрытия/переоткрытия окна) — без действия (в исходной версии провалы тихие). Найти причину, исправить.
- **Как:**
  1. Исходный `SendMacroTextRaw` молча глотал ошибки записи/таймаут/пустой парсинг — провалы после первого клика были невидимы.
  2. Диагностика: `SendMacroTextRaw` теперь возвращает `BOOL` + `pErr` (0=OK, 1=пусто/парсинг, 3=таймаут 5 с, 4=порт закрыт, >4=код ОС WriteFile); хендлер SEND показывает MessageBox с причиной. RUN-режим без изменений (результат игнорируется, тихое поведение как было).
  3. Гипотезы: (a) `WriteFile` падает со 2-го вызова (дескриптор инвалид, устройство перестало принимать); (b) порт закрывается авто-реконнектом (`TIMER_RECONNECT_ID`: `GetCommModemStatus` фейл → `com_close`, L2619); (c) парсинг=0.
- **Текущее состояние:**
  - сделано: корневая причина найдена — асинхронная запись (`WriteFile` → `ERROR_IO_PENDING`, `WaitForSingleObject` = `WAIT_OBJECT_0`): исходный `ok` остаётся FALSE → функция возвращала FALSE («код ОС 0») и пропускала эхо, хотя данные дошли до устройства. Фикс: успех определяется по `err` (0 = сsync OK или async завершён), эхо — по `err == 0`; пересборка `output\WT232_send.exe` OK
  - в работе: тест фиксированной сборки пользователем
  - не начато: подтверждение пользователя
- **Следующие 2–3 шага:**
  1. Пользователь: открыть порт, нажать SEND 2–3 раза → эхо при каждом успешном клике, MessageBox больше нет.
  2. Проверить RUN-режим: клики по макросам → эхо на каждый клик (тот же корневой дефект был в `SendMacroCommand`).
  3. Подтверждение → `[RESOLVED]`.
- **Решения:** | что | почему |
  | диагностика только в пути SEND (MessageBox) | RUN-режим сохраняет исходное тихое поведение; новый код — без компромиссов совместимости | 
  | успех по `err`, не по `ok` | `ok` — лишь первый ответ `WriteFile`; при `ERROR_IO_PENDING` реальный исход даёт `WaitForSingleObject`. Исходный паттерн `if (ok && echo)` терял эхо (и сообщал ложный сбой) на асинхронных записях — первый клик был синхронным (эхо было), остальные — асинхронными («ничего не отправилось»)
  | фикс в общем ядре `SendMacroTextRaw` | лечит одновременно SEND-кнопку и RUN-режим (один и тот же путь записи) | 
- **Открытые вопросы:** код ошибки из теста пользователя
- **Файлы для чтения:** `main.c` — `SendMacroTextRaw` (L1659), хендлер SEND в `MacroEditWndProc` (секция WM_COMMAND), `com_close`/`com_open` (L543/L640), reconnect-таймер `TerminalWndProc` (L2619)
- **Проверка:** сборка Pelles C; тест с конкретным кодом ошибки
