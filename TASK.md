## Активная задача

### Задача «Кнопка STOP не останавливает запущенный скрипт (терминал)» [EXECUTED]
- **Цель:** кнопки STOP в терминале и окне макросов останавливают запущенный скрипт (быстрый цикл A→B) в любом состоянии `.wts` на диске (файл есть / отсутствует / перемещён / пуст).
- **Первопричина:** в обоих обработчиках кнопок путь STOP стоит за проверкой `_waccess(scriptPath)` (файл существует): терминал — `IDC_BTN_RUN_SCRIPT` (main.c L2960-2972), макрос — `IDC_MACRO_BTN_RUN` (L2295-2308). Если `.wts` в момент клика отсутствует → MessageBox «Файл не найден» + ранний break/return — `StopGlobalScript`/`StopMacroScript` не достигаются, таймер продолжает скрипт. В сессии наблюдался перенос содержимого между файлами #0/#1/#2 (живое редактирование пользователем) — вероятный сценарий «нельзя остановить».
- **Дополнительно (тест-данные, без правки кода):** `##WAIT`/`##STOP` (двойной #) = комментарий для парсера → ни паузы, ни маркера → бесконечный цикл (интент пользователя «скрипт гоняется»); `#WAITВ SPACE` в `WT232#0.wts` (кирилл. В на 6-м месте) тоже молча отбрасывается парсером (line[5]∉{'\0',' ','\t'} → комментарий).
- **Как:**
  1. Обработчик терминала: `if (g_isScriptRunning) { StopGlobalScript(); break; }` перед всеми файловыми проверками; путь старта сохраняет _waccess + «Скрипт пуст!».
  2. Обработчик макроса: тот же паттерн (`if (g_macroScriptRunning[b]) { StopMacroScript(b); return 0; }` до проверки файла).
  3. `.wts` пользователя не трогаем (решение «как есть»); ранняя правка `##`→`#` в #0.wts уже сделана — отчитаться в ответе.
- **Текущее состояние:**
  - сделано: диагностика, фикс обоих обработчиков (main.c L2960 терминал / L2295 макрос: стоп-ветка до `_waccess`), dry-compile CC_EXIT=0
  - не начато: пересборка + ретест пользователем
- **Следующие 2–3 шага:**
  1. Пользователь: пересобрать в Pelles C (`WT232.ppj`) → ретест: цикл A→B + клик STOP в трёх состояниях `.wts` (есть/удалён/пуст) — должен останавливаться во всех
  2. не остановится после пересборки → запросить точный сценарий (текст кнопки в момент клика, появившиеся диалоги)
  3. Подтверждение → `[RESOLVED]`
- **Решения:** | что | почему |
  | стоп-порядок first в обоих обработчиках | остановка = очистка состояния (KillTimer + флаги); файл `.wts` не должен гейтить остановку — из-за этого и «нельзя остановить» |
  | `##`/`В` в `.wts` не чинить | «гоняется циклически» — тест-интент пользователя; тест-данные его («как есть») |
  | версия не поднимать пока | бамп версии — решение пользователя при релизе (паттерн v0.6.4/v0.6.5) |
- **Открытые вопросы:** «нельзя остановить» = файл отсутствовал в момент клика (покрывается фиксом) или устаревший exe? Ответит ретест.
- **Файлы для чтения:** `main.c` — L2295, L2960 (обработчики кнопок), L1526, L1594 (Stop-функции), L1533 (RunNextGlobalScriptCommand); `.notes/dry-compile.ps1`
- **Проверка:** dry-compile CC_EXIT=0 (сделано); ретест пользователя (3 состояния `.wts`)
