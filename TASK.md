## Активная задача

### Задача «Кнопка STOP не останавливает запущенный скрипт (терминал)» [EXECUTED]
- **Цель:** кнопки STOP в терминале и окне макросов останавливают запущенный скрипт (быстрый цикл A→B) в любом состоянии `.wts` на диске.
- **Диагноз (актуальный):** НЕ в `_waccess` (этот фикс уже сделан) и НЕ в `g_isScriptRunning`-guard (guard добавлен, не помог). Решающие наблюдения пользователя:
  1. при паузе 100 мс STOP срабатывает; при 60 мс — иногда; при 0 мс (голые `A\nB`) — почти никогда; эхо (галка Echo) не влияет.
  2. макроSTOP работает всегда (в т.ч. быстрый цикл) — а глобальный нет.
  3. глобальный скрипт пишет команды в строку отправки `g_hComboTx`; макро — «тихо» (GT не трогает). Идея пользователя: если терминальный скрипт тоже шлёт «тихо» — проблемы не будет.
  4. после закрытия/переоткрытия окна терминала клик по RUN сразу даёт «Скрипт остановлен» → флаг `g_isScriptRunning` НЕ сбрасывается при закрытии окна (старый тик живёт виртуально; см. правку 2).
- **Как (правки в `main.c`):**
  1. `RunNextGlobalScriptCommand` (тело ~L1535-1557): заменить строку `SetWindowTextW(g_hComboTx, cmd); com_send_ui(g_hwndTerminal);` на прямой путь «как в макро» (`RunNextMacroScriptCommand` ~L1624-1640): `parse_text_with_inline_hex(cmd, binBuf, ..., cp)` → `WriteFile` + `WaitForSingleObject(ovWrite.hEvent, 5000)` под `g_csComm` → эхо `append_echo_text`/`append_echo_hex_dump` по `is_echo_enabled()`. **Не трогать `g_hComboTx`** и не вызывать `com_send_ui`/MessageBox. При `binLen==0` не останавливать скрипт (комментарий = пропустить тик), просто продолжать.
  2. `WM_CLOSE` терминала (~L3005-3006, там уже `KillTimer(TIMER_SCRIPT_ID)`): добавить `if (g_isScriptRunning) StopGlobalScript();` (или `g_isScriptRunning=FALSE; g_scriptWaitKey=0;`) до `StopRxTxThreads()` — иначе после переоткрытия окна флаг остаётся TRUE и RUN даёт «Скрипт остановлен».
- **Текущее состояние:**
  - сделано: оба фикса `_waccess`-порядка (L2960/L2295), guard `if (!g_isScriptRunning) return;` в начале обеих `RunNext*`, индикаторы «Скрипт остановлен»
  - сделано (2026-11-01): правка 1 — `RunNextGlobalScriptCommand` (~L1551) шлёт напрямую как макро (`parse_text_with_inline_hex` → `WriteFile` под `g_csComm` + эхо), без `g_hComboTx`/`com_send_ui`; при `binLen==0` тик пропускается без остановки. Правка 2 — `WM_CLOSE` терминала: `if (g_isScriptRunning) StopGlobalScript();` перед `KillTimer`/`StopRxTxThreads()`
  - dry-compile: CC_EXIT=0, кодировка UTF-16 LE BOM сохранена (проверено `.notes/check-enc.ps1`)
- **Следующие 2–3 шага:**
  1. пользователь: пересобрать в Pelles C (`WT232.ppj`), запустить; ретест: быстрый цикл A→B в #0.wts + STOP; контроль: лейбл «Скрипт остановлен», кнопка «RUN», строка отправки «тихо»; доп.: закрыть окно при работающем скрипте → открыть → RUN запускает (не «Скрипт остановлен»)
  2. если STOP всё ещё не работает при быстром цикле — гипотеза о комбобоксе не подтверждена: копать блокировку GUI-потока (синхронный `WaitForSingleObject(5000)` в `WM_TIMER`) — рассмотреть вынос отправки из GUI-потока
  3. подтверждение → `[RESOLVED]`, свернуть запись в реестр
- **Решения:** | что | почему |
  | глобальный скрипт шлёт напрямую, как макро (без g_hComboTx / com_send_ui) | единственный зафиксированный путь, который при быстром цикле работает (макро); устраняет неизвестную блокировку, связанную с записью в g_hComboTx/перерисовкой комбобокса при 10 мс тике |
  | сброс g_isScriptRunning/FALSE в WM_CLOSE терминала | иначе флаг переживает закрытие окна → после переоткрытия RUN = «стоп» («Скрипт остановлен») |
  | guard g_isScriptRunning не удалять | полезен против queued WM_TIMER после стопа |
  | `.wts` пользователя не чинить; `##STOP`,`#WAITВ` = тест-интент «как есть» | решение прошлого витка сохранено |
- **Открытые вопросы:** точная причина блокировки при комбобоксе не доказана (эмпирическая симметрия с рабочим макро); если после правки 1 STOP заработает — гипотеза подтверждена, если нет — копать блокировку в записи (WaitForSingleObject в GUI-потоке).
- **Файлы для чтения:** `main.c` — L1535-1557 (RunNextGlobalScriptCommand), L1624-1640 (RunNextMacroScriptCommand — образец прямой записи), L3005-3006 (WM_CLOSE), L889 (com_send_ui — не использовать в скрипте); `.notes/dry-compile.ps1`
- **Проверка:** dry-compile CC_EXIT=0 + ретест пользователя (быстрый цикл + STOP, «тихо» в строке отправки)
