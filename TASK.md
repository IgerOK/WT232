## Активная задача [IN PROGRESS]

Задача «Сохранять размер окна макросов» [IN PROGRESS]
- **Цель:** окно макро-пада (класс `WT232_MacroPad_Class`, `g_hwndMacroPads[i]`) должно запоминать свой изменённый пользователем размер и восстанавливать его при следующем открытии, аналогично позиции (X/Y уже сохраняются). Файл: `main.c`.
- **Как:**
  1. Позиция уже пишется в `WM_MOVING` (`SaveMacroPadPosition`, секция `MacroPos_%d`, ключи X/Y). Добавить размер туда же: ключи W/H.
  2. `SaveMacroPadSize`/`LoadMacroPadSize` — аналог позиционных, пишет/читает W/H из `MacroPos_%d`.
  3. В `MacroPadWndProc` — новые `case WM_EXITSIZEMOVE`: сохранять позицию и размер через `GetWindowRect`.
  4. В `ShowMacroPad` — загружать сохранённый размер (`LoadMacroPadSize`), если он валиден, вместо жёстких `w = MACRO_COLS*70+30; h = MACRO_ROWS*30+100`.
- **Текущее состояние:**
  - сделано: объявления `SaveMacroPadSize`/`LoadMacroPadSize`; реализации после `LoadMacroPadPosition`; handler `WM_EXITSIZEMOVE`; загрузка размера в `ShowMacroPad`
  - в работе: ждёт сборки пользователем и проверки поведения
  - не начато: —
- **Следующие 2–3 шага:**
  1. Собрать проект в Pelles C (пользователь) → открыть окно макросов, изменить размер, закрыть, снова открыть — размер должен восстановиться (проверка через `WT232.ini`, секция `[MacroPos_%d]`, ключи W/H)
  2. При подтверждении — статус `[EXECUTED]`
- **Решения:**
  | что | почему |
  |---  |---    |
  | размер хранить в той же секции `MacroPos_%d` (X/Y/W/H) | позиция и размер — единое состояние окна |
  | сохранять в `WM_EXITSIZEMOVE`, а не в `WM_SIZE` | `WM_SIZE` идёт на каждый шаг ресайза; запись в ini — только по завершении |
  | `WM_MOVING` (позицию) не трогал | уже работает, минимальные правки |

- **Файлы для чтения:** `main.c` — `ShowMacroPad` (~L2102), `MacroPadWndProc` (~L1971), `SaveMacroPadPosition`/`LoadMacroPadPosition` (~L1606–1624)
