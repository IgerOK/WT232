## Активная задача

### Задача «SEND: срабатывает только с первого клика (+ тот же дефект в скриптах/автоответчике)» [IN PROGRESS]
- **Цель:** Первый клик SEND отправляет, последующие — без действия (тихие провалы). Плюс (по решению пользователя, в той же задаче): починить тот же дефект в `RunNextMacroScriptCommand` и автоответчике.
- **Как:**
  1. Диагностика: `SendMacroTextRaw` возвращает `BOOL` + `pErr` (0=OK, 1=пусто/парсинг, 3=таймаут, 4=порт закрыт, >4=код ОС); хендлер SEND показывает причину в MessageBox. RUN-режим — тихий как был.
  2. Корневая причина: асинхронная запись (`WriteFile` → `ERROR_IO_PENDING`, `WaitForSingleObject` = `WAIT_OBJECT_0`), но успех определялся по первому `ok` → ложный сбой + потерянное эхо. Фикс в `SendMacroTextRaw`: успех по `err`.
  3. Подтверждено пользователем: «Код проверил — работает».
  4. Расширение: `RunNextMacroScriptCommand` (L1536) и автоответчик в `TerminalWndProc` (L2662) — тот же паттерн `if (ok && echo)`; минимальная правка: при `WAIT_OBJECT_0` промоторить `ok = TRUE`, гейт эхо не трогать.
- **Текущее состояние:**
  - сделано: фикс ядра SEND/RUN (подтверждён); правки двух добавочных мест; пересборка `output\WT232_send.exe` OK
  - в работе: тест финальной сборки пользователем (макроскрипты + автоответчик)
  - не начато: финальное подтверждение
- **Следующие 2–3 шага:**
  1. Пользователь: запуск макроскрипта (SCRIPT) с эхом → эхо на каждую строку; автоответчик с эхом → эхо на каждый ответ.
  2. Подтверждение → `[RESOLVED]`.
- **Решения:** | что | почему |
  | диагностика только в пути SEND (MessageBox) | RUN-режим сохраняет исходное тихое поведение; новый код — без компромиссов совместимости | 
  | успех по `err`, не по `ok` | `ok` — лишь первый ответ `WriteFile`; при `ERROR_IO_PENDING` реальный исход даёт `WaitForSingleObject` | 
  | фикс в общем ядре `SendMacroTextRaw` | лечит одновременно SEND-кнопку и RUN-режим (один и тот же путь записи) | 
  | дофиксены только места с `if (ok && echo)`: макроскрипт + автоответчик | `com_send_ui` и `DoAutoSendTick` эхо по `ok` не гейтят (обратная особенность: эхо даже при неудаче) — изменение их поведения не входит в задачу; при желании — отдельной задачей | 
  | минимальная правка: промоторить `ok` при `WAIT_OBJECT_0` | тот же корень, минимальный дифф, тихие ошибки без изменений | 
- **Открытые вопросы:** —
- **Файлы для чтения:** `main.c` — `SendMacroTextRaw` (L1659), `RunNextMacroScriptCommand` (L1523), автоответчик `TIMER_AUTO_REPLY_ID` в `TerminalWndProc` (L2655)
- **Проверка:** сборка Pelles C; тест: SEND-клики, RUN-клики, макроскрипт и автоответчик с эхом вкл
