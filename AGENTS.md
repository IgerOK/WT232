# AllToZed — протокол контекста проекта для Zed

Этот файл — движок протокола: Zed-агент читает его автоматически при
открытии проекта. Память проекта живёт в `TASK.md` — едином источнике
истины (L2), хранится в git. Без кода, без установки, без зависимостей:
plain-файлы + git как транспорт памяти.

## Файлы

| Файл | Роль |
|---|---|
| `AGENTS.md` | Этот протокол. Читается автоматически. |
| `TASK.md` | Память проекта: активная задача, решения, следующие шаги, реестр. L2, git. |
| `.notes/` | Локальные заметки L1 (git-игнор). В перенос не входят. |
| git | Транспорт: память переезжает на другие машины и агенты вместе с проектом. |

## Формат `TASK.md` (жёсткие ограничения)

- Одна активная задача. Секция активной задачи ≤ 60 строк.
- Скелет — в шаблоне внутри `TASK.md` (цель, как, текущее состояние,
  следующие 2–3 шага, решения, открытые вопросы, файлы для чтения, проверка).
- «Следующие 2–3 шага» — конкретны настолько, что новый чат начинает работу
  без истории: файл — действие — как проверить.
- Решения: только решение + причина («X сделали, Y отбросили, потому что Z»).
  Новый чат их не переосмысляет.
- Пути и идентификаторы — дословно, как в коде. «та конфигация» не писать.
- Секреты, токены и личные данные в `TASK.md` не писать.
- Завершённые задачи сворачиваются в строку в секции «Реестр»:
  `цель — исход — дата`.

## Статусы

`[PLANNED]` → `[IN PROGRESS]` → `[EXECUTED]` → `[RESOLVED]`, строго
последовательно.

- **PLANNED** — задача записана в `TASK.md` до начала выполнения (что, как).
- **IN PROGRESS** — каждый завершённый шаг обновляет «Текущее состояние».
- **EXECUTED** — результат проверки + «Следующие 2–3 шага»; ждёт
  подтверждения пользователя.
- **RESOLVED** — только после явного подтверждения пользователя
  («подтверждаю» / «ок»); задача снимается с актива, запись реестра
  сворачивается в одну строку.

## Тихие триггеры записи

Агент обновляет `TASK.md` без диалога с пользователем в моменты:

- принято значимое решение или план изменён → «Решения» / «Как»;
- создан/изменён важный файл, поменялся TODO → «Текущее состояние»;
- вопрос закрыт → убрать из «Открытых вопросов»;
- шаг завершён → «Текущее состояние» + «Следующие шаги»;
- достигнут порог контекста (по глобальным правилам 0.55–0.65·W) или
  пользователь сказал «сохрани контекст» → финальное обновление + чек-лист
  handoff (см. «Resume»).

## Коммиты

- `TASK.md` коммитится вместе с кодовым изменением, которое она описывает —
  один коммит (lockstep): состояние и код всегда согласованы.
- Только локальный git: remote и push по инициативе агента — нет.

## Resume (новый чат)

Триггеры по умолчанию: «продолжаем» / «продолжи» / «далее» / «прочитай
TASK.md и продолжи активную задачу». Строка «Триггеры» в `TASK.md` имеет
приоритет: пользователь может там заменить, дополнить или исключить слова —
агент следует ей и больше не реагирует на снятые слова.

1. Прочитать `TASK.md`.
2. Health-check: активная задача есть; цель заполнена; «Следующие шаги»
   конкретны; ≤ 60 строк; пути из «Файлов для чтения» существуют; секретов
   нет.
3. Ответить в 3–5 строк: «Цель: … / Сделано: … / Дальше: … — идём?» и
   ждать «идём».
4. Продолжить строго с первого следующего шага.

Новому чату запрещено: переосмыслять «Решения», перечитывать файлы,
которые перечислены в «Файлах для чтения» и уже открыты, начинать новые
подзадачи, пока есть активная задача.

## Сбой handoff

Если health-check `TASK.md` провален, агент не выдумывает. Сообщает:
«TASK.md сломан (health-check FAIL)». Предлагает: (a) восстановить из
последнего рабочего git-коммита, (b) инициализировать заново. Начинает
только после выбора пользователя.

## Новый проект

Команда пользователя «Создай AllToZed для этого проекта»: агент копирует в
проект `AGENTS.md`, `TASK.md` (шаблон), `.gitignore`; заполняет в `TASK.md`
строки «Окружение» (W, профиль) и «Цель» по верхнему уровню структуры
(чужие решения не подхватывает); делает первый коммит; сообщает
«AllToZed инициализирован» и ждёт подтверждения.

## Язык

Рабочий язык — из строки «Рабочий язык» в `TASK.md` (по умолчанию русский).
Переключается, только если пользователь начал говорить на другом языке.

## Отношение к глобальным правилам

Глобальный `AGENTS.md` (пользовательский уровень) задаёт поведение: лимиты
токенов, git-дисциплина, режимы. Этот файл задаёт протокол памяти: формат
`TASK.md`, статусы, триггеры записи, resume и health-check. В конфликтах по
файлам памяти и статусам — приоритет у этого файла.
